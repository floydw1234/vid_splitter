# Smart Branching — Jellyfin Plugin

<!-- Concurrency smoke ticket 10 marker; docs-only note. -->

A Jellyfin plugin that provides age- and profile-aware video playback from `.bvf`
containers generated by the analyzer. `.bvf` files are first-class library media:
Jellyfin indexes them directly and the plugin serves profile-resolved streams.
Current runtime playback supports `play`, `swap`, and `skip`; manifests that
resolve to reserved `mute` or `blur` actions are rejected explicitly instead of
being treated like normal playback.

## Architecture

```
Python CLI (pre-processing)     ->    C# Jellyfin Plugin (playback)
----------------------------          --------------------------------
* analyze.py runs once per movie       * Registers .bvf as a video extension
* Generates Movie.bvf                  * Resolves .bvf into Movie/Video items
* Whisper + Safety Checker             * Serves resolved BVF segments
* BVF muxer embeds fMP4 assets/index   * Profile branching at play time
```

## Prerequisites

### Python Side (Pre-Processing)
- Python 3.10+
- FFmpeg installed on the system
- GPU optional for faster Safety Checker inference

### C# Side (Jellyfin Plugin)
- Jellyfin Server 10.9.x
- .NET 8.0 SDK or newer
- FFmpeg available to Jellyfin if playback paths invoke it

## Quick Start

### 1. Analyze a Movie

```bash
cd ~/Documents/codingProjects/vid_splitter
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
python analyzer/analyze.py "/path/to/Movie.mp4" --model base
```

Output:
- `Movie.bvf`
- `frames/` extracted analyzer frames, safe to delete after analysis

### 2. Build the Plugin

```bash
cd csharp_plugin
dotnet build SmartBranching.Plugin.sln -c Release
dotnet test SmartBranching.Plugin.sln -c Release
python scripts/package_plugin.py \
  --build-output bin/Release/net8.0 \
  --output-dir dist
```

Output:
- `bin/Release/net8.0/Jellyfin.Plugin.SmartBranching.dll`
- `bin/Release/net8.0/Jellyfin.Plugin.SmartBranching.deps.json`
- `bin/Release/net8.0/ZstdSharp.dll`
- `../csharp_plugin.Tests/bin/Release/net8.0/SmartBranching.Plugin.Tests.dll`
- `dist/smart-branching-0.1.0.0.zip`

The packaging script reads the runtime artifact list and release metadata from `build.yaml`,
verifies version parity with `Directory.Build.props`, packages only the declared runtime
artifacts, and updates `manifest.json` for the latest release.

### 3. Runtime Artifacts

`build.yaml` is the source of truth for packaged plugin metadata and runtime artifacts:

- `Jellyfin.Plugin.SmartBranching.dll`
- `Jellyfin.Plugin.SmartBranching.deps.json`
- `ZstdSharp.dll`

### 4. Install From A Plugin Repository

1. Build and package the plugin so `manifest.json` and the release zip are current.
2. Publish `manifest.json` at a stable URL and publish the generated `.zip` where the
   manifest's `sourceUrl` points.
3. In Jellyfin, open Dashboard -> Plugins -> Repositories.
4. Add the repository URL that serves this plugin's `manifest.json`.
5. Open the catalog, install **Smart Branching**, then restart Jellyfin if prompted.

### 5. Manual Offline Install From Zip

1. Build and package the plugin:

```bash
cd csharp_plugin
dotnet build SmartBranching.Plugin.sln -c Release
python scripts/package_plugin.py \
  --build-output bin/Release/net8.0 \
  --output-dir dist
```

2. Create the plugin directory in Jellyfin's plugin data path.
3. Extract `dist/smart-branching-0.1.0.0.zip` into the `SmartBranching` plugin directory.
4. Restart the Jellyfin server.

The packaged `.zip` is the supported offline install artifact. It contains only the runtime
files declared in `build.yaml`.

### 6. Update

1. Build a new plugin release and run `package_plugin.py` against the new build output.
2. If you use a plugin repository, publish the updated `.zip` and refreshed `manifest.json`.
3. In Jellyfin, update from the repository entry or replace the installed plugin directory
   with the contents of the new `.zip`.
4. Restart Jellyfin after the update.

### 7. Uninstall

1. Stop Jellyfin.
2. Remove the `SmartBranching` plugin directory from Jellyfin's plugins location.
3. Start or restart the Jellyfin server.
4. If installed from a custom repository, remove that repository entry from Jellyfin if it
   is no longer needed.

### 8. Developer-Only Fallback

For local debugging only, you can still copy unpacked build artifacts directly instead of
using the packaged `.zip`:

1. Create the `SmartBranching` plugin directory under Jellyfin's plugins path, such as
   `/var/lib/jellyfin/plugins/SmartBranching` on typical Linux installs.
2. Copy the three runtime artifacts from the build output into that directory.
3. Restart Jellyfin.

### 9. Configure

1. Open Jellyfin Web UI.
2. Go to Dashboard -> Plugins -> Smart Branching.
3. Configure smart branching, default profile, thresholds, filler directory, and per-profile overrides.

### 10. Play

1. Place `Movie.bvf` in a Jellyfin library folder (it is the media file).
2. Rescan the library. Jellyfin should list the BVF as a normal movie/video item.
3. If a same-stem `Movie.mp4` sits beside the `.bvf`, the plugin ignores the mp4 so only the BVF is indexed.
4. Play the item. If Jellyfin provides an authenticated request user during source enumeration, the plugin auto-selects that user's resolved Smart Branch profile and exposes a single `Smart Branch (auto: profile)` source.
5. If no authenticated user is available in the request context, the plugin falls back to exposing one Smart Branch source per BVF manifest profile.

Jellyfin 10.9's `IMediaSourceProvider` playback hook does not pass the active
user into `OpenMediaSource`. To keep playback deterministic, the plugin resolves
the authenticated request user during `GetMediaSources` when possible and encodes
the selected profile in the media source open token. When no request user is
available, it falls back to the previous per-profile source list.

## Verification

Use this checklist when validating the production playback path:

1. Confirm the library contains the `.bvf` file itself (not only a sibling mp4).
2. Refresh Jellyfin discovery after generating or replacing the `.bvf`.
   A successful smoke run should queue an item refresh when the movie is already known to Jellyfin, then poll until Smart Branch media sources appear.
3. Verify that Jellyfin exposes one Smart Branch media source per BVF manifest profile.
   The expected source names look like `Smart Branch (adult)` or `Smart Branch (child)`.
4. Verify playback readiness through Jellyfin's playback-info path.
   The smoke harness checks that `POST /Items/{itemId}/PlaybackInfo` returns at least one playable media source for the selected Smart Branch source and does not report an `ErrorCode`.

If Smart Branch sources do not appear:

- Re-check that the `.bvf` is inside a scanned library path and that the plugin is enabled.
- Validate the `.bvf` locally with `python3 tools/bvf_probe.py /path/to/Movie.bvf`.
- Inspect Jellyfin logs for plugin messages.
  The default server log is typically `/var/log/jellyfin/server.log`.
  Example: `grep SmartBranching /var/log/jellyfin/server.log`

## BVF Manifest Reference

See `BVF_SPEC.md` and `PROJECT_SPEC.md` for the BVF manifest schema.

Key fields:
- `segments[].tags`: content tags such as `nudity`, `violence`, `language`, `fear`, `gore`
- `segments[].risk`: `safe`, `mature`, or `restricted`
- `segments[].media`: fMP4/CMAF asset metadata for the indexed payload
- `segments[].profiles`: per-profile action and target segment mapping
- Runtime-supported profile actions: `play`, `swap`, `skip`
- Reserved manifest actions rejected by current runtimes: `blur`, `mute`

## Troubleshooting

### Plugin not appearing in Jellyfin
- Check that the DLL is in the plugins directory.
- Verify Jellyfin version matches `targetAbi` in `build.yaml`.
- Check Jellyfin logs for plugin load errors.

### No Smart Branch source appearing
- Ensure the `.bvf` is inside a Jellyfin library path and the plugin is installed/enabled.
- Verify the BVF parses with the Python reader or reference player.
- Check plugin logs: `grep SmartBranching /var/log/jellyfin/server.log`.

### Segments not playing
- Check file permissions; the Jellyfin user must be able to read the `.bvf`.
- Verify the segment index offsets and lengths with BVF reader tooling.
- Ensure FFmpeg is installed and in PATH if the active playback path requires it.
### Analysis fails
- Check FFmpeg is installed: `ffmpeg -version`.
- For large files, use a smaller Whisper model: `--model tiny` or `--model base`.
- GPU helps significantly with Safety Checker; ensure CUDA is available when expected.
