# Task Plan: Smoke 03 isolated lifecycle marker

## Objective

Add a single independent documentation artifact at `docs/terarchitect-smoke/ticket-03.md` with the exact required content, without changing runtime behavior.

## Constraints and assumptions

- Use TDD: add a failing automated test before creating the markdown file.
- Keep the change isolated and independently mergeable.
- Do not modify application code or existing runtime behavior.
- No integration environment, web service, Docker Compose stack, or UI/E2E surface is involved in this ticket.
- No external test data is required because the artifact is a static markdown file and the validation can be done with a small pytest document-content check.

## Files expected to change

- `docs/terarchitect-smoke/ticket-03.md`
- `tests/test_terarchitect_smoke_ticket_03.py`

## Order of work

1. Inspect existing smoke-marker precedent and current docs test patterns.
   - Reconfirm the local convention already observed in files such as `README.md`, `PROJECT_SPEC.md`, `BVF_SPEC.md`, and the small pytest checks that validate marker presence.
   - Dependency: none.

2. Add a new failing pytest focused only on this ticket.
   - Create `tests/test_terarchitect_smoke_ticket_03.py`.
   - Test should assert:
     - `docs/terarchitect-smoke/ticket-03.md` exists.
     - The first top-level heading is exactly `# Terarchitect Smoke Ticket 03`.
     - The file contains the exact line `Ticket: 03`.
     - The file contains the exact line `Purpose: verify competing attempts, winner selection, acceptance, and Ship Room composition on an isolated file.`
     - The file includes a short independence note stating that it is intentionally independent of the other nine smoke tickets.
   - Keep the assertions narrow and text-based so the failure clearly identifies missing or incorrect required content.
   - Example assertion style snippet:
     - `assert "# Terarchitect Smoke Ticket 03" in lines[:3]`
   - Dependency: step 1.

3. Run the targeted test and confirm it fails for the expected reason.
   - Run pytest only for the new test module first to verify the red phase.
   - Expected failure: missing file or missing required content.
   - Dependency: step 2.

4. Implement the minimum documentation artifact to satisfy the test.
   - Create `docs/terarchitect-smoke/ticket-03.md`.
   - Add only the required heading and required lines, plus one short independence note.
   - Avoid adding unrelated sections, links, shared references, or broader smoke-ticket documentation.
   - Dependency: step 3.

5. Re-run the targeted test and confirm it passes.
   - This validates the green phase with the minimum implementation.
   - Dependency: step 4.

6. Refactor only if the test or document structure needs cleanup.
   - Prefer no refactor unless there is unnecessary wording or a brittle assertion.
   - If refactoring is needed, keep behavior identical and preserve the exact required lines.
   - Dependency: step 5.

7. Run a small relevant regression slice.
   - Run the new test plus any nearby doc-oriented tests that could reveal unintended documentation-test coupling.
   - Recommended regression subset:
     - `tests/test_terarchitect_smoke_ticket_03.py`
     - `tests/test_readme_docs.py`
     - `tests/test_bvf_spec_doc.py`
     - `tests/test_csharp_plugin_readme.py`
   - Dependency: step 6.

8. Review final diff for isolation.
   - Confirm only the plan’s intended repo files changed for implementation: one new docs file and one new pytest file.
   - Verify no runtime code, packaging assets, or unrelated docs were modified.
   - Dependency: step 7.
