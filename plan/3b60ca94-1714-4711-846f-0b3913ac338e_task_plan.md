# Task Plan: Smoke 07: add isolated lifecycle marker

## Ticket summary

Create a new documentation-only smoke marker at `docs/terarchitect-smoke/ticket-07.md` with exact required content:

- top-level heading: `# Terarchitect Smoke Ticket 07`
- exact line: `Ticket: 07`
- exact line: `Purpose: verify competing attempts, winner selection, acceptance, and Ship Room composition on an isolated file.`
- short note stating the file is intentionally independent of the other nine smoke tickets

This ticket must not modify runtime code behavior.

## Constraints and repo context

- The repo already uses lightweight smoke markers in docs/comments, with pytest checks that validate documentation markers by reading files directly.
- There is currently no `docs/terarchitect-smoke/` directory in this checkout, so the implementation will need to create it.
- There is no `docker-compose` file, no app service startup path, and no frontend E2E framework in the repo root; those parts of the standard planning template are not applicable here.
- Because this is a docs-only ticket, the most appropriate TDD shape is a small pytest file that fails until the target markdown artifact exists with the exact required lines.

## Files expected to be touched

- `tests/test_terarchitect_smoke_ticket_07.py`
- `docs/terarchitect-smoke/ticket-07.md`

Potentially touched only if needed during refactor:

- no additional files expected

## Step-by-step execution plan

1. Review existing documentation-marker test patterns.
   - Re-open existing examples such as `tests/test_bvf_spec_doc.py` and `tests/test_csharp_plugin_readme.py`.
   - Confirm the preferred assertion style in this repo: direct file reads, exact/substr checks, and minimal scope.
   - Dependency: none.

2. Add a new failing pytest test first.
   - Create `tests/test_terarchitect_smoke_ticket_07.py`.
   - Write a focused test that:
     - resolves the repo root with `Path(__file__).resolve().parents[1]`
     - targets `docs/terarchitect-smoke/ticket-07.md`
     - fails if the file does not exist
     - reads the file as UTF-8
     - asserts the first line is exactly `# Terarchitect Smoke Ticket 07`
     - asserts one line is exactly `Ticket: 07`
     - asserts one line is exactly `Purpose: verify competing attempts, winner selection, acceptance, and Ship Room composition on an isolated file.`
     - asserts the document includes a short independence note mentioning that it is intentionally independent of the other nine smoke tickets
   - Keep the test isolated from unrelated smoke markers; it should inspect only this file.
   - Example assertion shape:
     - `assert lines[0] == "# Terarchitect Smoke Ticket 07"`
     - `assert "Ticket: 07" in lines`
   - Dependency: step 1.

3. Run the new test by itself and confirm it fails.
   - Command shape:
     - `env PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest tests/test_terarchitect_smoke_ticket_07.py`
   - Expected failure mode:
     - missing file or missing required exact lines
   - Record the failure mentally as the TDD red phase.
   - Dependency: step 2.

4. Implement the minimum documentation artifact to satisfy the failing test.
   - Create the directory `docs/terarchitect-smoke/` if it does not already exist.
   - Create `docs/terarchitect-smoke/ticket-07.md`.
   - Add only the required content plus a brief independence note.
   - Avoid adding unrelated headers, cross-links, generated metadata, or references to the other smoke ticket files.
   - Keep the file intentionally standalone so it matches the ticket’s “isolated lifecycle marker” requirement.
   - Dependency: step 3.

5. Re-run the focused test and confirm it passes.
   - Re-run:
     - `env PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest tests/test_terarchitect_smoke_ticket_07.py`
   - This is the TDD green phase.
   - Dependency: step 4.

6. Check for broader regressions in documentation-related tests.
   - Run the nearest relevant existing tests to ensure the new docs directory/file does not conflict with current conventions.
   - Recommended suite:
     - `env PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python3 -m pytest tests/test_readme_docs.py tests/test_bvf_spec_doc.py tests/test_csharp_plugin_readme.py tests/test_terarchitect_smoke_ticket_07.py`
   - Rationale:
     - these are the repo’s closest existing file-content documentation checks
   - Dependency: step 5.

7. Refactor only if the new test is unnecessarily brittle.
   - Prefer no refactor unless needed.
   - If needed, keep changes limited to the new test file, for example:
     - normalize line endings with `splitlines()`
     - use exact line membership for required fields instead of substring scanning across the full file
   - Do not refactor production/runtime code because this ticket must not alter behavior.
   - Dependency: step 6.

8. Final verification and change review.
   - Confirm only the planned files were added/modified.
   - Review the markdown file for exact required text and no accidental formatting drift.
   - Review the test for isolation: no dependency on ordering, no dependency on external services, no dependency on other smoke ticket files.
   - Dependency: step 7.
