# Task Plan: Reject unsupported BVF profile actions in C# reader

## Objective
Harden the shared C# BVF runtime resolver so that:
- profile actions outside the runtime-supported set (`play`, `swap`, `skip`) fail explicitly instead of falling back to normal playback
- `swap` actions that point at a missing segment fail explicitly instead of being skipped silently
- focused C# tests cover both behaviors and assert `InvalidDataException` messages

## Scope and constraints
- Do not change Python behavior in this ticket unless needed for fixture parity/reference only.
- Prefer fixing the shared reader path in `Assets/Scripts/BVFReader.cs` so all C# consumers inherit the same validation behavior.
- Keep exception semantics aligned with malformed BVF/runtime data: use `InvalidDataException`.
- Keep tests fixture-based and minimal; no external services, web servers, Docker, or fixed ports are needed for this ticket.

## Files expected to touch
- `Assets/Scripts/BVFReader.cs`
- `csharp_plugin.Tests/BVFReaderManifestTests.cs`
- Possibly `csharp_plugin/SegmentServer.cs` if a small follow-up alignment/refactor is needed after reader hardening

## Order of work

### 1. Baseline the current behavior
1. Inspect `Assets/Scripts/BVFReader.cs` and confirm the exact runtime-resolution branch in `GetSegments(Stream, string)`.
2. Inspect `csharp_plugin.Tests/BVFReaderManifestTests.cs` to reuse its temporary BVF builder pattern.
3. Run the relevant C# test project once to establish a baseline before changes.
   - Command to plan for: `dotnet test csharp_plugin.Tests/SmartBranching.Plugin.Tests.csproj`
4. Confirm there are currently no C# tests covering unsupported runtime actions or missing swap targets.

Dependency:
- This step informs the exact assertions and helper reuse for the next test additions.

### 2. Add failing C# tests for unsupported runtime actions first
1. Update `csharp_plugin.Tests/BVFReaderManifestTests.cs` with a focused runtime-resolution test that builds a tiny BVF fixture whose profile action resolves to `mute`.
2. Convert that case into a parameterized test if practical so the same test covers both `mute` and `blur`.
3. Structure the test in AAA style:
   - Arrange: create or mutate a minimal manifest JSON fixture with one non-filler segment and a profile entry such as `"action": "mute"`
   - Act: call `BVFReader.GetSegments(bvfFile, "child")`
   - Assert: `Assert.Throws<InvalidDataException>(...)` and verify the message mentions unsupported runtime playback action and the offending action value
4. Run the C# test project and confirm the new test fails for the expected reason before implementation.

Planned snippet shape only:
- Profile entry like `"child": { "action": "mute", "segment_id": "seg-001" }`
- Assertion target like `Unsupported BVF action for runtime playback: 'mute'`

Dependency:
- Requires the existing temp BVF helper or a small extension to it.

### 3. Add failing C# test for missing swap target second
1. In `csharp_plugin.Tests/BVFReaderManifestTests.cs`, add a separate focused test for a `swap` action whose `segment_id` names a segment absent from the BVF index.
2. Reuse the same fixture builder, but create a manifest where the narrative segment profile resolves to something like `"action": "swap", "segment_id": "missing_999"` while the BVF index contains only the original segment.
3. Act by calling `BVFReader.GetSegments(bvfFile, "child")`.
4. Assert `InvalidDataException` and check the message includes both the source segment and the missing target identifier, or at minimum the missing target and the fact that it does not exist.
5. Run the C# test project and confirm this new test also fails before implementation.

Dependency:
- This test depends on the temp BVF fixture helper being able to create at least one indexed segment while the manifest references another nonexistent one.

### 4. Implement the minimum reader change to satisfy the failing tests
1. Edit `Assets/Scripts/BVFReader.cs` in `GetSegments(Stream, string)`.
2. Introduce explicit runtime-action validation before segment resolution.
   - Normalize the action once.
   - Allow only `play`, `swap`, `skip`.
   - Throw `InvalidDataException` for anything else.
3. Preserve `skip` behavior unchanged.
4. For `swap`, resolve the target segment id explicitly.
   - If the action is `swap` and the target id is empty or whitespace, decide whether to keep current fallback-to-source behavior or fail explicitly.
   - The ticket only requires failure for missing swap targets, but while implementing, verify whether empty/blank target should also be treated as invalid data for consistency. If the existing tests/spec do not require it, keep scope narrow and avoid widening behavior without a test.
5. When the resolved target segment id is not present in the segment index, throw `InvalidDataException` instead of silently omitting the segment.
6. Keep the implementation minimal and local to the reader; avoid broader refactors in this step.

Planned logic shape only:
- Validate action via a helper or inline branch such as `if action not in { play, swap, skip } -> throw InvalidDataException(...)`
- On missing target: throw with a message like `BVF segment 'seg-001' resolves to missing target 'missing_999'`

Dependency:
- Must be driven by the failing tests from steps 2 and 3.

## Implementation notes to keep in mind
- The spec in `BVF_SPEC.md` already says runtimes must reject `mute` and `blur`; the C# reader should enforce that contract directly.
- The Python reference player already rejects unsupported actions, so the C# reader behavior should converge toward that explicit-failure model.
- Prefer stable exception messages that mention the action or missing target explicitly so the tests remain meaningful.
- Avoid pasting manifest files into tests; keep fixtures minimal and inline.

## Expected outcome
After completion:
- `BVFReader.GetSegments(..., profile)` rejects unsupported runtime actions with `InvalidDataException`
- `BVFReader.GetSegments(..., profile)` rejects missing swap targets with `InvalidDataException`
- the C# test suite contains focused regression coverage for both cases
