## Risks To Watch During Implementation

- Accidentally changing the default human-readable output format and breaking the existing CLI test.
- Emitting extra text alongside JSON, which would break `json.loads(...)` for agent workflows.
- Serializing Python tuples in a way that tests do not expect; JSON decoding will normalize them to lists, so assertions should reflect that.
- Broadening scope into extraction or media-probing behavior when the ticket is only about CLI output mode.

## Definition Of Done

- `analyzer/filler.py` supports `--json`.
- Default behavior remains human-readable without `--json`.
- JSON mode emits a parseable JSON object containing exactly the ticket-required fields.
- `tests/test_filler.py` covers both default text mode and JSON mode.
- Targeted pytest verification for the filler test file passes.
