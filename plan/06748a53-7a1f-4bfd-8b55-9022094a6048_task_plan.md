### 4. Implement the minimum parser hardening in `analyzer/topic_classifier.py`

- Update `_parse_topics` only after the failing tests are in place.
- Keep the parsing strategy layered and conservative:

1. First try `json.loads(content)` on the full response.
   - This covers compliant plain JSON without extra extraction logic.

2. If that fails, search markdown fenced code blocks and try to parse their contents.
   - Prefer fenced blocks labeled `json`, but also consider unlabeled triple-backtick blocks if they contain a plausible array.

3. If fenced parsing fails, search for a plausible JSON array substring inside surrounding explanatory text.
   - Avoid the current broad “first `[` to last `]`” approach if a narrower extraction method is feasible.
   - The goal is to reduce over-capture from unrelated bracketed text while still handling `Topics: ["politics"]`.

4. After any successful JSON parse, accept only list values and filter each element against `self.topics`.

5. Preserve a final conservative fallback only if it still adds value after the structured extraction steps.
   - If kept, ensure it does not become more permissive than the new tests justify.

- If the code becomes hard to read inline, add a small private helper such as `_validate_topic_list(...)` or `_extract_json_array_candidate(...)`.
- Do not expand scope into API request changes like Structured Outputs in this ticket unless there is an existing local pattern to follow; that is a separate improvement.
