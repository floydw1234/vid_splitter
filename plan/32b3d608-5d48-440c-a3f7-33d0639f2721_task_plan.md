# Ticket Plan: Production 03 real analyzer and BVF/keyframe validation

## Goal
Turn the currently skipped real-video analyzer path into a practical validation workflow for short videos, and expand BVF validation from manifest-only checks into media-aware verification using `ffprobe` and exported MP4 outputs.

## Constraints and assumptions
- Do not implement analyzer/model-heavy coverage against arbitrary production media in CI. Keep automated integration coverage based on generated or committed test fixtures that are short and deterministic.
- Prefer `ffmpeg`/`ffprobe` as the required validation backend because the repo already depends on them in integration tests and runtime utilities.
- There is no app web service or `docker-compose` stack in this repo today, so the plan does not introduce service startup or port management steps.
- The current analyzer appears to remux fragmented MP4 assets but does not yet prove source-boundary keyframe snapping. Plan for validator tests to expose that gap before changing analyzer behavior.

## Test data plan
1. Reuse generated short videos in existing ffmpeg-backed tests, extending helper coverage rather than introducing long binary fixtures immediately.
2. Add deterministic generated fixtures for keyframe-sensitive scenarios:
   - a short H.264/AAC video with fixed GOP, e.g. `-g 24 -keyint_min 24`
   - a short filler/replacement clip with distinct audio/video characteristics
   - if needed, a deliberately misaligned cut case generated from a known source video so the validator can prove boundary failures
3. Only add committed binary test data under a dedicated directory such as `tests/data/` if generated fixtures cannot reliably reproduce the keyframe/pathology cases.
4. Keep all generated clips short, ideally 2-8 seconds, so `ffprobe`-based integration tests remain practical.

### 2. Expand BVF structural validation in TDD order
1. Write failing unit-style tests in [tests/test_bvf_probe.py](/tmp/terarchitect_worker_thwhetog/repo/tests/test_bvf_probe.py) for structural invariants beyond the current manifest checks:
   - header `segment_count` matches index entry count
   - manifest `segments` count matches indexed assets count where appropriate
   - each index `segment_id` matches a manifest/media asset entry
   - each `data_offset`/`data_length` points inside the file and to a parseable `BVA\\0` block
   - asset block header `segment_id` matches the index entry it belongs to
2. Implement the minimum code in [tools/bvf_probe.py](/tmp/terarchitect_worker_thwhetog/repo/tools/bvf_probe.py) to make those tests pass.
3. Refactor probe internals into small helpers only after the new assertions pass, for example:

Dependency:

### 3. Add ffprobe-backed media validation for embedded assets
1. Write failing integration-style tests in [tests/test_bvf_probe.py](/tmp/terarchitect_worker_thwhetog/repo/tests/test_bvf_probe.py) or a new probe integration test module for:
   - a valid BVF generated from a short real MP4 fixture returns success and reports probe metadata
   - an invalid BVF with fake payload bytes like `b"ftyp...."` fails with a clear media probe error
   - duration mismatch between manifest/index and extracted asset duration is detected
   - container mismatch or missing video stream is detected
2. Reuse or extend existing helper generation from [tests/test_cli_e2e.py](/tmp/terarchitect_worker_thwhetog/repo/tests/test_cli_e2e.py) instead of duplicating ffmpeg fixture code.
3. Implement minimum validator support in [tools/bvf_probe.py](/tmp/terarchitect_worker_thwhetog/repo/tools/bvf_probe.py):
   - extract each indexed asset block payload to a temp file
   - run `ffprobe` with machine-readable JSON output
   - validate stream presence, codec/container expectations, and independently decodable payloads
   - compare probed duration to index duration and manifest timeline with a small tolerance
4. Refactor only after passing:
   - centralize `ffprobe` invocation
   - centralize tolerance calculations and error formatting

Dependency:

## Risks to watch
- Fake `media_payload` bytes used in current tests may remain useful for negative tests, but positive media validation needs real ffmpeg-generated payloads.
- Keyframe validation can be brittle if assertions depend on codec-specific frame metadata; prefer fixture-controlled H.264 output and clear tolerances.
- Export duration comparisons should allow a small tolerance for muxing/reporting drift instead of requiring exact millisecond equality.
- Heavy analyzer tests should remain opt-in; CI should rely on deterministic generated-video cases to stay practical.
