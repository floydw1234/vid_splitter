# Task Plan: 44162f88-9ca8-487d-b82d-2c8d8a0568d4

## Ticket

Production 01: real Jellyfin playback smoke harness

## Goal

Add a repeatable, production-oriented smoke workflow that:

1. Picks a small real video from `/mnt/hdds/Videos/shorts` when available.
2. Generates a sibling `.bvf` next to the movie.
3. Triggers Jellyfin discovery/rescan safely.
4. Verifies Smart Branch media-source discovery for the movie.
5. Verifies playback readiness through Jellyfin’s HTTP API.
6. Skips cleanly with explicit reasons when Jellyfin URL, credentials/token, or media paths are unavailable.

## Constraints And Observations

- Existing repo support already covers:
  - deterministic BVF generation via `analyzer/analyze.py --demo-branch`
  - BVF validation via `tools/bvf_probe.py`
  - Jellyfin plugin media-source exposure in `csharp_plugin/SegmentServer.cs`
  - skip-friendly real-data tests in `tests/test_real_video_integration.py`
- There is no `docker-compose.yml` or other compose file in this repo.
  - `docker compose up -d` / dynamic host port planning is therefore not applicable unless a later implementation step decides to add new local orchestration assets.
  - For this ticket, prefer targeting an already-running Jellyfin instance through env-configured URL/auth instead of introducing a new container stack.
- There is no frontend app or browser E2E framework in the repo.
  - UI automation is not applicable for this ticket unless implementation later adds a web-client harness, which is not currently justified.
- The current project targets Jellyfin 10.9.x / `net8.0`, so the harness should verify against the current plugin contract rather than newer plugin-template assumptions.

## Environment Contract To Plan Around

Prefer env vars over hardcoded machine-specific values. Expected inputs:

- `JELLYFIN_BASE_URL`
- `JELLYFIN_API_KEY` or `JELLYFIN_USERNAME` + `JELLYFIN_PASSWORD`
- `JELLYFIN_USER_ID` if item queries require explicit user scoping
- `JELLYFIN_LIBRARY_ROOT` or a movie path under the mounted Jellyfin library
- `JELLYFIN_SHORTS_DIR`
  - default planned fallback: `/mnt/hdds/Videos/shorts`
- `RUN_JELLYFIN_SMOKE=1`
  - explicit opt-in gate for the pytest integration test

The test and script should emit skip messages like:

```text
SKIPPED: set JELLYFIN_BASE_URL and JELLYFIN_API_KEY (or username/password) to run Jellyfin smoke
```

## Risks To Watch During Implementation

- Jellyfin item lookup by path may vary by server/library configuration.
  - Plan to keep lookup logic flexible and test multiple fallback strategies.
- Library refresh is asynchronous.
  - Plan to poll for discovery rather than assuming immediate visibility.
- Real library content must not be mutated beyond writing the sibling `.bvf`.
  - Avoid renames, moves, deletions, or full-library destructive operations.
- Authentication setup may differ between API-key and username/password environments.
  - Support both, with API key preferred for non-interactive smoke runs.
- This repo currently has no container orchestration for Jellyfin.
  - Do not add Docker complexity unless implementation proves it necessary.

## Explicit Non-Goals For This Ticket

- No new bundled media assets in the repo.
- No fixed localhost ports.
