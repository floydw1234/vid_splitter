# Task Plan: 1a5c3689-55a0-4f2b-b194-655c95089968

## Goal

Replace the eager `MemoryStream` assembly path in [`csharp_plugin/SegmentServer.cs`](../csharp_plugin/SegmentServer.cs) with lazy streaming of resolved BVF segment payloads, while preserving profile resolution behavior (`play` / `swap` / `skip`) and adding the best seek/range support the current `ILiveStream.GetStream()` architecture can reasonably provide.

## Constraints And Current State

- Current hot path:
  - [`SegmentServer.OpenMediaSource()`](../csharp_plugin/SegmentServer.cs) creates a `BvfLiveStream`.
  - `BvfLiveStream.GetStream()` calls `BuildResolvedStream(...)`.
  - `BuildResolvedStream(...)` reads every resolved segment into RAM and appends payload bytes into one `MemoryStream`.
- Existing reusable primitives:
  - [`ResolveAllSegmentsForProfile()`](../csharp_plugin/SegmentServer.cs) already computes resolved segment order and skip/swap behavior.
  - [`BVFReader.OpenSegmentDataStream()`](../Assets/Scripts/BVFReader.cs) already opens a bounded stream for one BVF block.
- Architectural gap:
  - [`BoundedReadStream`](../Assets/Scripts/BVFReader.cs) is non-seekable.
  - There are no current tests for lazy streaming, cross-segment reads, or seek behavior.
- Test environment:
  - No `docker-compose.yml` / `compose.yml` is present in the repo.
  - No UI/E2E harness is present, and this ticket does not touch frontend code.

## Order Of Work

1. Add characterization tests around the current resolved-segment behavior so the refactor does not break skip/swap resolution.
2. Add new failing unit tests for a lazy composite stream abstraction before introducing the new stream implementation.

## Key Design Decisions To Validate During Implementation

- Whether to make the underlying per-segment reader itself seekable in `BVFReader.cs`, or keep `BVFReader` simple and implement seek translation entirely in the composite stream.
- Whether the composite stream should reopen the BVF file on segment switches/seeks or keep one file handle and reposition it.
  - Initial bias: keep one open file stream per composite stream instance if possible, because that simplifies seeking and reduces reopen churn.
- Whether tests should assert exact stream type.
  - Initial bias: assert “not `MemoryStream`” only if the API surface makes that stable; otherwise assert behavior that proves laziness/seekability.
