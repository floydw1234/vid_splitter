# Task Plan: Smoke 08: add isolated lifecycle marker

## Scope

Create a single isolated Markdown artifact at `docs/terarchitect-smoke/ticket-08.md` with the exact required heading and metadata lines from the ticket, without changing application behavior.

## Constraints and Observations

- The ticket is explicitly independent of other smoke tickets, so avoid modifying shared files such as `README.md`, `PROJECT_SPEC.md`, `BVF_SPEC.md`, or `csharp_plugin/README.md`.
- The repo already uses pytest to enforce documentation expectations in files like `tests/test_readme_docs.py` and `tests/test_csharp_plugin_readme.py`, so the safest TDD path is to add one small docs-focused pytest file for this artifact.
- There is no `docker-compose.yml` or frontend/UI test harness in the repo, and this ticket does not touch runtime services or web surfaces.

## Files Planned

- New test: `tests/test_terarchitect_smoke_ticket_08.py`
- New document: `docs/terarchitect-smoke/ticket-08.md`

## Step-by-Step Execution Plan

1. Add a focused failing test for the new smoke marker file.
   - Create `tests/test_terarchitect_smoke_ticket_08.py`.
   - Assert that `docs/terarchitect-smoke/ticket-08.md` exists.
   - Assert that the file contains:
     - a first-level heading exactly `# Terarchitect Smoke Ticket 08`
     - a line exactly `Ticket: 08`
     - a line exactly `Purpose: verify competing attempts, winner selection, acceptance, and Ship Room composition on an isolated file.`
     - a short note stating the file is intentionally independent of the other nine smoke tickets
   - Keep the assertions literal and narrow so the test fails only on missing or malformed required content.
   - Suggested style: read the file text once, then assert exact lines with simple string checks or line-based matching.

2. Run the targeted test and confirm it fails before implementation.
   - Run a narrow pytest command against the new test file only.
   - Expected initial failure: missing file at `docs/terarchitect-smoke/ticket-08.md`.
   - This establishes the red phase of TDD and avoids unrelated test noise.

3. Implement the minimum documentation artifact to satisfy the failing test.
   - Create the directory `docs/terarchitect-smoke/` if needed.
   - Add `docs/terarchitect-smoke/ticket-08.md` with only the required content plus the short independence note.
   - Keep formatting simple and stable:
     - heading on the first line
     - exact `Ticket:` and `Purpose:` lines on their own lines
     - one short plain-language note below, for example a sentence that says this file is intentionally independent from the other nine smoke tickets
   - Do not add YAML frontmatter, HTML comments, links, or unrelated prose.

4. Re-run the targeted test and confirm it passes.
   - Run the same pytest command used in step 2.
   - Verify the new test passes with no additional behavior changes required.

5. Refactor only if the test or file structure is noisier than necessary.
   - Prefer no refactor unless needed.
   - If refinement is needed, keep it limited to:
     - simplifying assertion wording in the new test
     - tightening the independence-note assertion so it remains robust without being brittle about full sentence wording
   - Do not broaden the change into shared docs cleanup or smoke-marker normalization across the repo.

6. Run a lightweight regression check for documentation tests.
   - Run the new test plus the existing doc-oriented tests that are most likely to detect accidental collateral changes, such as:
     - `tests/test_readme_docs.py`
     - `tests/test_bvf_spec_doc.py`
     - `tests/test_csharp_plugin_readme.py`
   - This stays proportional to the scope while confirming the new docs addition does not disturb established docs checks.

7. Review the final diff for isolation and merge safety.
   - Confirm the diff contains only:
     - `tests/test_terarchitect_smoke_ticket_08.py`
     - `docs/terarchitect-smoke/ticket-08.md`
   - Confirm there are no code-path, packaging, workflow, or shared-doc edits.
